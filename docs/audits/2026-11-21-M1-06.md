## Findings
1. **[high, latent] The inner iteration is only conditionally convergent, and the margin is about 1.2× at the allowed maximum.** The fourth-order operator's stencil is not diagonally dominant (centre 20 vs Σ|off-diagonal| 44), so undamped Jacobi, including two-color Jacobi, diverges once `Δt·a_ii` gets large. Measured threshold: ≈ 75× the explicit capillary Δt. `SEMI_IMPLICIT_ACCURACY_FACTOR = 64` with `dtSafety ≤ 1` allows 64×, and the odd/even ripple there is the onset. The app runs at `dtSafety 0.2` (≈ 12.8×, plus the GPU hint's 10% margin), so it's safe today, but any change to dtSafety, sweep count or the cap walks into it silently, and the code comment says the opposite.
   **Fix (M1-06b):** make the inner solve convergent at any Δt. The simplest is **damped Jacobi** with ω chosen from the stencil bound (ω ≈ 0.5; Jacobi on `I + c·B` converges for ω < 2/ρ(D⁻¹A) ≈ 2/3.2). Alternatives: a proper symmetric smoother, or a split into a coupled 2nd-order system. Then the 64× cap really is just an accuracy cap.
2. **[medium] The accuracy test was weakened from the criterion.** It used σ = 8 mN/m, dtSafety 0.5 and 4 steps, where the task said "64² puddle" with default physics. Default params actually do *better* (above), so this is a test-quality issue, not a physics one. M1-06b restores the default-params test.
3. **[low] The doc comment misdescribes the cap** ("accuracy … not stability"). Fix it with finding 1.
4. **[info]** Throughput can't be checked from a hidden pane. The structure (15–29 semi substeps per 1/60 s frame) is consistent with Δt ≈ 12.8× explicit at 512².
