## Findings
1. **[medium] The import-boundary rule misses React subpaths.** `paths` only matches exact module names, so `react-dom/client`, `react-dom/server` and other `react/*` subpaths get through. Fix: add `react`, `react/*`, `react-dom` and `react-dom/*` to the `patterns` group (or use `patterns` with `group: ['react', 'react/*', 'react-dom', 'react-dom/*']`) in `eslint.config.js`.
2. **[medium] `.nvmrc` pins Node 20, which reached end-of-life in April 2026.** CI would run on an unsupported runtime, and the local machine has Node 26. Fix: set `.nvmrc` to `24` (active LTS) and `engines.node` to `>=22`.
3. **[low] `tsconfig.vitest.json` adds `vitest/globals` types, but `vitest.config.ts` doesn't set `globals: true`.** The types say `describe`/`it` exist globally when they don't at runtime. The tests import them explicitly, so nothing breaks today. Fix: drop the `types` entry (preferred, explicit imports) or enable `globals`.
4. **[low] `@types/node` is `^26` while the engines floor is Node 20.** Types for newer Node APIs could let code through that fails on the floor version. Align with whatever finding 2 settles on.
5. **[info] npm 11 blocked esbuild's postinstall script** (`npm warn install-scripts`). The build still works through esbuild's platform package, so no action is needed, but don't approve install scripts without checking them.
6. **[info] Scope:** `zustand` was added early, which the handoff notes disclose. Acceptable since it's in the agreed stack.
