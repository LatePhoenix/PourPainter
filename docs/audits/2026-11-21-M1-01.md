## Findings
1. **[high] Clamping negative heights creates paint.** `setCell(next, …, hNew > 0 ? hNew : 0)` adds back any overshoot below zero, and nothing accounts for it. Near sharp fronts and dry regions that's a steady mass gain, confirmed above, and it grows over a session. It also hides the true conservation error from the tests.
   **Fix:** a positivity-preserving flux limiter. For each cell, compute total outgoing flux × dt. If it exceeds the cell's volume, scale that cell's outgoing face fluxes by `available / outgoing` before the update, applied consistently to both neighbors sharing a face. Volume is then exactly conserved, the clamp becomes unnecessary (keep an assert that h ≥ −ε), and the edge-drain accounting uses the limited fluxes.
2. **[high] The centered gravity flux oscillates.** The in-plane gravity term `M·ρ·g∥` uses the face-averaged `h`, so it's centered differencing of a nonlinear advection (kinematic-wave) term. With forward Euler that makes dispersive wiggles at fronts (confirmed above), which would show up as false ridges in the painting.
   **Fix:** use **upwind** mobility for the gravity term: take `h` from the upwind cell according to the sign of `g∥` on that face. Keep the centered mobility for the pressure (diffusive) terms. Add a test: after tilted flow, the center row has a single maximum (no interior local minima above a small tolerance).
3. **[medium] The capillary dt bound is 4× too generous in theory.** Von Neumann analysis of explicit Euler on the 2D biharmonic (5-point Laplacian applied twice) gives `Δt ≤ Δ⁴ / (32·M·σ)`; the code uses `Δ⁴/(8·M·σ)`. It survives today because `M` uses the global max h, and the default safety is 0.2. The noisy-film probe at safety 1.0 already behaves differently from the lower settings. The kinematic wave speed is also `dq/dh = h²ρg∥/μ`, which is 3× the `u_max` used.
   **Fix:** use the analytic bounds (`/32`, and wave speed `h²ρ|g∥|/μ`). Document that `dtSafety` may then range up to 1. Add a **checkerboard** stability test: a uniform film plus ±1% checkerboard, capillary only, at `dtSafety = 0.9`. The checkerboard amplitude must decay.
4. **[low] The tilt doc comment contradicts the code.** The comment says tiltX > 0 sends flow "toward grid +y (down the texture)". The code gives g∥y < 0, toward the canvas top, which is physically right for "the +Y side tips down". Fix the comment, and add a test pinning both axes' signs. This orientation is exactly the kind of bug that's painful to find later in the UI.
5. **[planning, not a code defect] Explicit capillary flow can't run in real time at our resolution.** With realistic parameters, one 60 Hz frame needs about 525 substeps at 512² and about 8,000 at 1024². The step count needed to simulate a given amount of flow doesn't depend on viscosity (it scales as σ·L/(ρ·g·Δ⁴)), so tuning μ won't help. M1-02's "≥ 60 fps at 512²" criterion is unlikely to be met at physical sim speed. See **ADR 0003 (proposed)**: keep the explicit solver as the reference, add a semi-implicit capillary step for the real-time GPU path, and change M1-02 to *report* throughput (sim-seconds per wall-second) rather than gate on 60 fps.
