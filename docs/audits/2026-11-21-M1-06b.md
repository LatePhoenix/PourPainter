## Round 1

- **Date:** 2026-11-21
- **Branch / commits:** task/M1-06b-damped-jacobi @ 8e0b6af
- **Verdict:** **changes** (one focused fix). The damped Jacobi itself is correct and works, on both CPU and GPU. But the CPU step also gained a **CPU-only "uniform shift" fallback**. It is non-physical, it makes results *less* accurate, and it means the CPU reference no longer computes what the GPU computes. Remove it.

## What's good
- **The damping derivation is correct:** Fourier symbol 0…64/dx⁴, diagonal 20/dx⁴, so ρ(D⁻¹A) = 3.2, and damped Jacobi converges for ω < 2/3.2 = 0.625. ω = ½ gives a worst-mode factor of 0.6. It's documented at the top of `thinFilmSemi.ts`, and it lives in the old pad slot of the uniform struct (still 48 bytes, round-trip OK).
- The accuracy test now uses **default** params, and the ripple test (roughness within 10%, one interior maximum) was added as specified.
- Throughput unchanged: Cursor reports 60 fps, 22 substeps/frame, 1.00 sim-s/wall-s at 512². Compare: semi 1.84e-6.
- `npm run check` 88/88; GitHub Actions success on 8e0b6af.

## The problem: the uniform-shift fallback (`thinFilmSemi.ts` ~L509–619)
If any *unlimited* flux-form height is < −1e-6, or any cell differs from h\* by > 0.2 mm, the CPU step:
1. discards the conservative finite-volume update,
2. keeps the unconverged iterate h\*,
3. adds **one constant to every cell on the canvas** (dry cells included) to balance volume,
4. clips negatives and **rescales the whole film**.

That moves paint non-locally (paint can appear on, or vanish from, dry canvas far from any flow), and **the GPU never does it**. The new 200×/1000× stability tests pass *through* this path, so they don't show that the damping alone is stable.

### Evidence (throwaway probes; dx = 300/512, default paint, 64², 0.25 s vs the explicit reference; dt = k × the explicit capillary Δt of the current field, as the app does)

| Case | CPU (with fallback) | GPU (damped Jacobi + limited flux, no fallback) |
|---|---|---|
| Puddle, k = 12.8 (app default) | 0.01%, corner 2.77e-7 = explicit ✅ (no fallback) | — |
| Puddle, k = 64 | 0.21%, corner = explicit ✅ (no fallback) | — |
| **Pour-like spike** (3 mm on a 1 mm puddle), k = 64 | **3.8%**, dry corner **zeroed** (fallback fired) ❌ | **0.31%**, corner 1.85e-7 = explicit ✅ |
| Pour-like spike, k = 200 | 25.6% ❌ | **5.2%**, bounded, no NaN, peak 1.036 vs 1.041 ✅ |

So the plain damped-Jacobi + limiter path is stable *and* more accurate. The fallback only hurts, and M1-04's pouring creates exactly this spike shape.

## Findings
1. **[high] Remove the uniform-shift fallback.** CPU and GPU must use the same commit: the limited flux form `hⁿ − Δt ∇·(q_ex + q_cap(h*))` with the M1-01 donor limiter, always. Restore the `h ≥ −1e-6` assert *after* limiting. Delete `SEMI_IMPLICIT_FLUX_RESIDUAL_MM`.
2. **[high] Re-prove stability on that path.** The 200×/1000× noise tests must pass with the fallback removed. Requirement: finite, peak ≤ the initial peak, volume (canvas + drained) within 1e-6, and noise std decreasing. If 1000× doesn't meet "std decreasing" on the flux path, report the numbers in the handoff notes; boundedness and conservation are the hard requirements.
3. **[medium] Add a pour-spike test,** the case that exposed this. A 1 mm Gaussian puddle plus a 3 mm spike (radius 1.5 cells) 6 cells off-center, 64², default params, 0.25 s, dt = 64 × the current explicit capillary Δt. CPU semi vs explicit rel L∞ < 1%, and the far-corner height within 1e-6 of explicit. Add the same case to the GPU "Compare to CPU" harness: GPU semi vs CPU semi < 1e-3.
4. **[low] Test runtime.** The suite went from about 2 s to about 14 s. Give the heavy semi tests explicit timeouts (≥ 60 s) so CI runners don't hit Vitest's 5 s default (see the M1-01 CI failure). Shrink grids or step counts where that doesn't weaken the check.
