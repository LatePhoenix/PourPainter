## Findings
1. **[high, latent] `physics.ts` mixes unit systems.** Lengths and gravity are in mm (`GRAVITY_MM_S2 = 9810`), but surface tension is in N/m (0.035) and density in g/ml (1.2). Plugged straight into the thin-film equations with mm lengths, `σ` comes out 1000× too weak or strong and `ρ` 1000× off, so capillary and gravity terms would be wildly unbalanced. Nothing uses the constants yet, so no bug exists today, but M1-01 would hit it immediately.
   *Root cause is partly ours:* the Cursor rule `10-simulation.mdc` said "mm, s, Pa·s, N/m", which isn't a consistent set. That rule is now corrected.
   **Fix (M0-02b):** adopt the consistent **mm–g–s** system. Pressure in g/(mm·s²) is exactly Pa, and viscosity in g/(mm·s) is exactly Pa·s, so μ values don't change. Surface tension becomes g/s² = **mN/m** (35, not 0.035), and density becomes **g/mm³** (1.2e-3, not 1.2). Keep human-friendly inputs (g/ml in `Paint`) but export a converter, and add a sanity test: capillary length √(σ/ρg) ≈ 1.7 mm for the defaults.
2. **[medium] The color space is mislabeled.** `Rgb` says "linear 0–1", but the preset values were clearly picked as sRGB (e.g. ultramarine `[0.18,0.22,0.62]`). Rendered as linear, everything comes out much lighter and washed out. Fix: store **sRGB** in the domain (matches color pickers), and convert to linear in the render pass.
3. **[medium] Fractional seeds collide.** `seed >>> 0` truncates, so 1.2 and 1.9 replay identically, and `parseRecipe` accepts any finite number as a seed. Fix: require the seed to be an integer in [0, 2³²) in `parseRecipe`, and have `createRng` throw on a non-integer seed. Also add a golden-value test (the first few outputs for a fixed seed) so a refactor can't silently change replays.
4. **[medium] The recipe parser checks types but not meaning.** It accepts dangling `paintId`s (cup layers and pour actions), empty or duplicate paint ids, non-positive canvas sizes, negative volumes or densities, rgb outside 0–1, and negative or unsorted `t`. A corrupted saved recipe would get as far as the sim before failing. Fix: add a `validateRecipe` step (used by `parseRecipe`) with tests for each rule. Keep coordinates unclamped if tools may start off-canvas, but document that choice.
5. **[low] The split cup has no compartment info.** `CupLayer` has no slot or side, so a split cup can't say which paint goes in which half. This is fine until M2, so it's noted on M2.
6. **[info] Densities are relative, not lab values.** The handoff notes disclose this. The ordering matches the plan, and that's what matters for buoyancy.
